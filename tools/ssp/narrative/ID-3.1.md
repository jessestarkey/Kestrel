In the cloud, no service should need a stored secret to reach the data it uses. Every IL5 workload will therefore use the platform's native identity, either AKS workload identity or a managed identity federated to Entra ID, scoped to its own spoke. Azure Machine Learning compute and Container Instances groups take managed identities as well. With those in place, services read the data lake zones, the report index, and the model endpoints without holding any credential. The on-premises data lake accepts the same federated tokens.

Pipelines get identities of their own, with tighter limits. A team's runner reaches only that team's dev/test spoke, and only the protected release runner can deploy to a release target. Any static credential that turns up in a cloud spoke is removed once a native identity can take its place.
