# Outcome Narratives

Each file here is named for one SADD outcome, such as `ID-1.1.md`, and holds that outcome's narrative in the SSP. A file named for a capability, such as `ID-1.md`, holds the short opening that ties its outcomes together. An outcome with no file shows its schedule from the Security Implementation Plan instead.

**Tense shows status.** Write a planned outcome in the future tense, saying what KESTREL will do, from its Security Implementation Plan record. Once the outcome's work reaches Done on the board, rewrite it in the present tense, from what was actually delivered. Name the deployed products and where they run, say what is not yet done, and leave configuration values to the governing plan, which the SSP links.

Write each narrative as plain prose a reader can follow without the SADD open. A few short paragraphs is enough. Keep the house style: short direct sentences, no em dashes, no semicolons, and bare control IDs.

The board sets the status. To record a deliberate gap tracked by a POA&M item, start the file with this line, then a blank line:

```
**Status:** Does Not
```
